# TouchDeck 产品路线

> 本文档是产品路线的唯一事实来源。当前路线以“单一场景的可靠指令闭环”为主线；其他方向不得绕过本文档自行进入开发。

## 定位

**TouchDeck = 平板远控桌面 GUI 编程 Agent 的触控操作层。**

远程桌面负责呈现 Codex 等桌面 GUI 编程 Agent 的完整界面，TouchDeck 补上平板或手机上难以快速完成的组合键、长文本、语音和不中断焦点的高频命令入口。

首要用户是通过 UU、Parsec 或 RDP，在平板上远程操作 Windows 桌面 GUI 编程 Agent 的人。成熟的终端映射已经能提供接近本地的终端体验，TouchDeck 不与其竞争；它解决的是桌面 GUI Agent 在平板远控下控件密集、快捷键难触达、操作成本高，而移动端原生 Agent 功能仍不完整的折中场景。

当前只验证一个 GUI 编程 Agent 工作流，以 Codex 这类带完整桌面界面的 Agent 为首个目标。

核心承诺：

- 指令不抢焦点，并落到预期目标。
- 用户按下后能明确知道结果，而不是猜测是否执行。
- 常用动作低带宽、低认知负担、可重复完成。

## 当前范围锁定

当前只做一个场景：**平板远控桌面 GUI 编程 Agent**。

场景内只保留 8–12 个经过真实使用验证的高频动作，候选包括发送、中断、语音、粘贴，以及 GUI 内经真实验证的导航动作。不得预设终端专用键位；具体动作必须以目标 Agent 的真实界面验证为准。

现有多布局、多主题、宏和场景解析机制属于代码基础，不等于当前要继续扩张的产品范围。当前禁止：

- 第二个或第三个场景预设。
- 通用 GUI 配置编辑器、自由拖拽画布和任意组件。v0.3.0 只允许为既定动作提供快捷键预设选择与自定义组合键，不借此开放按钮、布局或脚本编辑。
- 插件 API、在线模板市场和配置分享平台。
- 条件分支、变量、循环判断和脚本语言。
- iOS、macOS、Linux 或通用远控扩张。
- 只为视觉丰富而进行的大型主题重构。

新增需求必须回答：是否直接提升“正确执行、明确反馈、快速触达”之一？不能回答“是”的需求延后。

## 阶段路线

路线顺序固定为：**可靠执行 → 安全配对 → 单一黄金工作流 → 轻量自定义 → 可交付**。

### v0.2.2：可靠指令闭环（P0，已完成受控验证）

目标：远程端每次按键都形成可追踪的执行闭环。

必须完成：

- 每次按键生成唯一 `requestId`，贯穿 Android、WebRTC、Windows 执行器和日志。
- 统一状态：`queued`、`executed`、`blocked`、`failed`、`disconnected`、`timeout`。
- `executed` 只在 Windows 宏真实执行完成后返回。
- 目标检查在入队和实际注入前都执行；前台探测失败时带目标的按钮必须拦截。
- 同一 `(clientId, requestId)` 最多执行一次，支持安全重试。
- 非法消息、未知按钮、队列溢出和执行异常不能导致任一端崩溃或静默等待。
- Android 能区分等待、成功、拦截、失败、断线和超时，反馈不能只依赖颜色。
- 日志可以按 `requestId` 定位，但不得记录提示词、剪贴板正文、输入文本或凭据。

出口标准：连续 100 次关键操作可追踪，成功率不低于 99%，错误窗口注入为 0，静默失败为 0；自动化测试覆盖状态机和异常路径。

### v0.2.3：安全配对（P0，已完成受控验证）

目标：在扩大真实使用前，避免裸 6 位房间码成为唯一安全边界。

必须完成：

- 每台新设备使用独立的短期一次性配对凭据；Host 可在上一枚被消费或过期后为下一台设备生成新凭据。
- Host 身份可验证，陌生端不能直接取得指令发送权。
- 信令使用加密连接并限制错误尝试。
- TURN 使用临时凭据并明确中继状态。

可靠闭环和安全配对不得拆成两个可公开分发的中间版本。当前 P2P 仅适合受控测试。

出口标准：每枚配对密钥只能在 5 分钟内成功登记一台新设备；Host 可为第二台设备生成另一枚密钥，旧枚不能重放；手机和平板续连只能使用各自已登记的设备凭据；错误主机凭据和错误配对尝试被明确拒绝；真实 Android 与 Windows 经公网 DataChannel 完成双设备首次配对和设备凭据续连；自动测试覆盖首次配对、第二设备配对、续连、重放拒绝、主机恢复拒绝、限速与临时 TURN 凭据格式。

### v0.3.0：单一黄金工作流（P1）

目标：让陌生用户无需修改 JSON，就能在平板上完成一次可靠的桌面 GUI 编程 Agent 远程操作。

动作预设先经过独立设计关卡，详见 [GUI Agent 工作流动作预设设计](workflow-preset-design.md)：

- 语音、中断、发送是 Owner 已确认稳定的 3 个固定动作，不因候选讨论而回退。
- 固定的是动作语义，不是键位或触发模式；锁定动作和候选动作都允许用户无需修改 JSON 即可选择快捷键预设或录入自定义组合键，并在自定义时选择单击触发或按住保持。
- 同一动作有多个已知可靠入口时提供带工具名称、实际键位和触发模式的下拉预设；Codex 听写使用“按住保持”，微信输入法与 Windows 语音输入使用“单击触发”，自定义由用户选择。
- 首轮候选已完成双真机验证：保留换行、粘贴、命令菜单、清空输入、按词删除和 `/` 命令入口；审阅变更与搜索任务在真实 Codex 窗口无可见结果，已从产品和绑定模型移除。以上 6 项与 3 个锁定动作组成当前 9 动作实验预设。
- Steer、批准/拒绝虽是高价值需求，但在没有稳定快捷键、运行状态或批准对象识别前，不得用焦点猜测和盲注入实现。
- 现有布局里的其他按钮是历史候选，不自动视为 v0.3.0 默认动作。

出口标准：

- 安装到首次成功触发控制在 10 分钟内。
- 默认提供 8–12 个高频动作，不发布多个半成品场景。
- 用户可在 Windows Host 控制台为每个默认动作选择已知预设或自定义单组组合键及触发模式；无需编辑 JSON，修改后同步到本机与 Android 展示。
- 绑定设置覆盖重复/冲突提示、单项恢复和全部恢复；1.0 前不承担旧配置迁移，测试版配置结构变化时可重置，并要求用户重新选择语音方案和快捷键。
- Codex 听写完成真实按住链路：手指稳定按住后 Windows `keyDown`，松开或取消后 `keyUp`；开始/结束使用同一标识并有分阶段反馈，断线、进程退出和最长保持超时均能兜底释放，任何测试后不得遗留按下状态。
- 每个新增默认动作都在当前 Windows Codex 真界面验证快捷键、焦点、误触后果和恢复路径。
- 每个语音预设都完成“平板说话 → 远程麦克风 → Windows 输入工具 → Codex 输入框出现文字”的端到端验证，不能只验证面板弹出。
- Owner 连续真实使用至少 7 天，记录按钮频率、失败率、重连和误触，不记录内容。
- 首次配对后能立即完成发送和中断测试。

### v0.3.1：轻量自定义（暂缓）

只有当单一预设及 v0.3.0 的快捷键绑定设置无法覆盖真实工作流，且问题不能通过新增通用动作解决时，才进入此阶段。

允许范围仅为按钮名称、图标、顺序、显隐和基础宏；快捷键预设与自定义组合键已经前置到 v0.3.0。不做自由画布、插件和条件逻辑。

### v0.3.2：本机键鼠交互增强（已完成）

目标：无键盘或不想移动鼠标点击球时，也能快速触达菜单；展开反馈更细腻。两个需求都直接提升“快速触达”与“明确反馈”。

必须完成：

- 鼠标中键触发悬浮球菜单展开/收起，菜单以**鼠标当前位置**为锚点展开；本机无键盘时也能单手触发。与球/菜单的主键交互隔离，中键不误触选中。
- 径向菜单展开动画精细化：扇区由内向外逐环出现（最里环先出），同一环内各项再叠加随机小时间差，动画节奏更快但保留逐项涌现的质感。

出口标准：

- 中键按下展开菜单、再按收起；菜单锚点在鼠标位置，无键盘依赖；悬浮球/菜单的点击选中不受中键干扰。
- 展开动画从内环到外环逐项涌现，环间、项间有明显时间差且整体快速完成；原有交互（hover、左击确认、Tab 确认）不回归。

完成证据：Owner 在 150% DPI 可见预览中反复重定位并确认旧位置残影与双层球消失；自动验证覆盖渲染回执、快速双按竞态、完整测试、类型检查与 Electron 构建。2026-08-21 因当前输入链路把前进侧键改写为普通左键，触发键改为系统可稳定识别的鼠标中键。

### v0.4.0：可交付（暂缓）

可靠性和安全性稳定后，再考虑签名安装包、诊断页、自动更新和公开测试流程。

## 决策门槛

继续投入的必要证据：

- 用户日均实际触发至少 20–30 次，连续 7 天仍使用。
- 关键操作成功率达到 99% 以上，错误窗口注入和静默失败为 0。
- 每次操作可通过 `requestId` 在 Android 与 Windows 两端定位。
- 用户反馈的是缺少具体动作或工作流约束，而不是单纯要求更多视觉和布局自由。

停止扩张的条件：核心按钮使用频率低、可靠性未达标，或 TouchDeck 相比直接操作远程桌面没有显著降低 GUI Agent 的操作成本。

## 当前执行顺序

1. 已完成既定动作的快捷键绑定设置、Codex 听写保持链路和异常释放。
2. 已完成 8 个首轮候选的真实 Codex 双真机验证，并淘汰无可见结果的审阅变更与搜索任务。
3. 已形成 3 个稳定动作加 6 个通过候选的 9 动作实验预设，本开发环节通过。
4. 连续收集 7 天真实使用数据，记录频率、失败、重连、误触、改键原因和相对直接操作远程桌面的成本，不记录输入内容。
5. 根据证据在 8–12 个动作内增删；Steer、批准等状态相关动作须先满足安全门槛。
6. 通过 7 天证据决定是否进入轻量自定义；在此之前不开发通用 GUI 配置编辑器。
7. 已完成本机交互增强（v0.3.2）：鼠标中键在鼠标位置展开菜单，径向菜单逐环逐项涌现，并消除非 100% DPI 下的传送残影与双层球。
